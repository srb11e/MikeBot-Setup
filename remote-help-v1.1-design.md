# Remote Help v1.1 — Design Document

**Status:** Design approved. Implementation in progress on `feature/remote-help-v1.1`.
**Target:** v1.1 (not part of v1.0 Mike release).
**Scope:** Optional support tools. Never part of the default MikeBot setup flow.

---

## 1. Architecture Decision

Remote Help gives Shands command-line access to Mike's Windows laptop
for troubleshooting when the bot or setup is stuck.

| Layer | Tool | Purpose |
|-------|------|---------|
| GUI support (first line) | Microsoft Quick Assist | Screen sharing, annotations, remote control. Already documented in README-FOR-MIKE.md v1.0.1. |
| Network | Tailscale | Private WireGuard mesh network. NAT traversal, no port forwarding. |
| Shell | Windows OpenSSH Server | Standard SSH daemon. Key-based auth only. |
| Access control | Windows Firewall | Inbound TCP 22 restricted to Tailscale IPv4 CGNAT range 100.64.0.0/10. |
| Authorization | sshd_config | PubkeyAuthentication yes, PasswordAuthentication no, ChallengeResponseAuthentication no. |
| Consent | Explicit typed phrase | Mike must type `ENABLE REMOTE HELP` and `DISABLE REMOTE HELP`. |
| Rollback | State file | `%LOCALAPPDATA%\MikeBot-Setup\remote-help-state.json` drives Disable-RemoteHelp.ps1. |

**Explicitly NOT used:** Tailscale SSH. It is unsupported on Windows (Tailscale issue #4697).

---

## 2. Security Constraints

- No Tailscale auth keys committed, embedded, logged, or written to disk.
- One-time, short-lived, tagged auth key generated by Shands (tag: `tag:mikebot-support`).
- No PowerShell transcript in Remote Help scripts.
- Custom log at `%LOCALAPPDATA%\MikeBot-Setup\remote-help.log`.
- Never log: auth key, full `tailscale up` command, SSH private key, user input, secrets.
- SSH exposed only via Tailscale. Firewall restricts inbound TCP 22 to 100.64.0.0/10.
- Microsoft's broad OpenSSH-Server-In-TCP rule is disabled if found. Never auto-restored.
- Configured for the currently logged-in Windows user. Stated explicitly in script output.

## 4. Firewall Behavior

- Remove any existing `MikeBot-RemoteHelp-SSH-Tailscale-Only` rule before creating.
- Create: Allow inbound TCP 22 only from `100.64.0.0/10`.
- Detect Microsoft's `OpenSSH-Server-In-TCP`. If enabled, disable it. Log in state.
- Disable-RemoteHelp.ps1 removes only the MikeBot rule.
- Broad Microsoft rule is NOT auto-restored. Manual re-enable instructions printed.

---

## 5. sshd_config Strategy

1. Back up to `sshd_config.backup-YYYYMMDD-HHmmss`.
2. Remove any previous `# BEGIN MIKEBOT REMOTE HELP` / `# END MIKEBOT REMOTE HELP` block.
3. Scan remaining config with multiline regex for conflicting directives.
4. If conflicts exist: STOP. Write failure state. Recommend Quick Assist.
5. If safe: Insert MikeBot block near the top (before substantive directives) so settings are the first obtained value.
6. OpenSSH uses **first-obtained-value** semantics, not last-match.
7. Handle Windows `Match Group administrators` → `administrators_authorized_keys` redirect.

Conflict checks (all uncommented):
- `PubkeyAuthentication no`
- `PasswordAuthentication yes`
- `ChallengeResponseAuthentication yes`
- `KbdInteractiveAuthentication yes`
- `AuthenticationMethods` containing `password`
- Non-default `Match` blocks

---

## 6. Authorized Key Strategy

- Determine whether the SSH login user is treated as an administrator by Windows OpenSSH.
- If admin AND default `Match Group administrators` block is active:
  → `%ProgramData%\ssh\administrators_authorized_keys`
- Otherwise:
  → `%USERPROFILE%\.ssh\authorized_keys`
- Key comment: `shands-remote-help-mikebot`
- Remove any previous MikeBot-marked key before adding fresh.
- ACL: administrators file → SYSTEM + BUILTIN\Administrators. User file → SYSTEM + user SID.
- Disable removes only the MikeBot-marked key line.

## 7. Test Matrix

| # | Scenario | Expected |
|---|----------|----------|
| 1 | Clean enable | All phases pass, state shows enabled=true |
| 2 | Clean disable | All artifacts removed, enabled=false |
| 3 | Re-run Enable twice | Idempotent, no duplicate artifacts |
| 4 | Disable after partial failure | Rollback uses state file, doesn't crash |
| 5 | Tailscale already installed/connected | Detected, not disconnected on failure |
| 6 | Tailscale not installed | winget install or manual fallback |
| 7 | OpenSSH Server already installed | Not re-installed, tracked in state |
| 8 | OpenSSH Server not installed | Installed via Add-WindowsCapability |
| 9 | Broad firewall rule enabled | Disabled, logged in state |
| 10 | Broad firewall rule disabled | Left disabled, not touched |
| 11 | Local admin account | Key goes to administrators_authorized_keys |
| 12 | Standard account | Key goes to ~/.ssh/authorized_keys |
| 13 | Microsoft account | SID-based ACL works |
| 14 | SSH reachable over Tailscale IPv4 | Shands can connect via `ssh user@100.x.x.x` |
| 15 | SSH NOT reachable from LAN/public | Firewall blocks non-Tailscale IPs |
| 16 | No auth key in logs or state | Verified by inspection |
| 17 | Disable removes only MikeBot artifacts | Other SSH/firewall config untouched |
