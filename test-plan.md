# End-to-End Test Plan — MikeBot Setup

**Prerequisites:** A Windows machine that hasn't been groomed for development. Ideally a real OEM laptop with manufacturer software still present. If using a VM, install a consumer AV trial (McAfee or Norton) and sign in with a Microsoft account that has OneDrive Known Folder Move enabled. Files must arrive via browser download (not git clone, not USB, not network share) so the Mark-of-the-Web flag is applied.

**Production distribution note:** If Mark-of-the-Web blocks execution, the production path delivers pre-unblocked files (via zip from a trusted source, USB, or a method that doesn't apply MotW). Step 1 characterizes the failure mode so you know what Mike would see if he re-downloads the files outside the standard distribution.

**Known gap (not addressed now):** DeepSeek free-credit exhaustion (HTTP 402). If Mike's account runs out of credits mid-conversation, the bot silently fails. Check platform.deepseek.com → Billing. Not a script remediation item — documented for awareness.

| Step | What to do | What failure looks like |
|------|-----------|------------------------|
| **1. SmartScreen gate** | Download the 4 files as a .zip via browser (or individually). Right-click each .ps1 and .bat → Properties → confirm "This file came from another computer" block message is present. Then double-click `Setup-MikeBot.bat`. | SmartScreen blocks with a different dialog than the README describes (e.g., no "More info" link, or Windows 11 shows a different flow). If blocked with no bypass path, Mark-of-the-Web must be removed via `Unblock-File` or the zip needs to be delivered differently. |
| **2. UAC + script launch** | Click Yes on UAC prompt. Verify the black PowerShell window appears with the welcome message and colored text. | UAC prompt doesn't appear (already admin?) or the PS window flashes and closes immediately (execution policy). Check the README's troubleshooting matches reality. |
| **3. Stage 4 winget installs under Defender** | Let winget install Git, Node.js, Telegram Desktop. Watch for any Defender popups, slowdowns beyond 2-3 min per package, or quarantine notifications. | Defender quarantines an installer → winget exit code is non-zero, script shows `[X] install failed`. Recovery path: Mike needs to open Windows Security → Protection history → allow the blocked item, then resume. Script doesn't handle this — Shands intervention required. |
| **4. OEM AV interference check** | Before starting, check if McAfee, Norton, or another consumer AV trial is active. If yes, note which one. During Stage 4 installs and Stage 9 (npm install -g openclaw), watch for: script execution blocked, network calls intercepted, installers silently killed. | AV blocks PowerShell script execution → window closes without error. AV intercepts npm network calls → install hangs at "Installing OpenClaw via npm" with no progress for 10+ min. **Flagged as known variable** — no script-side mitigation exists. Recovery: temporarily disable the AV's script-scanning or real-time component, or have Mike coordinate with Shands. |
| **5. Stages 6–7: resume with keys already saved** | Complete Stage 6 (Telegram token saved, progress written). Close the window. Re-launch. Confirm resume prompt offers Stage 7 (not Stage 6). Now run through Stage 7, paste the DeepSeek key, then close the window *immediately* after "DeepSeek key saved" appears but before Stage 8 starts. Re-launch. Check whether Stage 7 re-prompts or skips. | Save-Progress now fires immediately on key save (not at end-of-block). If Stage 7 re-prompts, the fix didn't close the gap. |
| **6. OneDrive sync verification** | Let the full setup complete. Log into onedrive.live.com with the same Microsoft account. Navigate to the OneDrive file view. Confirm `MikeBot-Setup` does NOT appear anywhere in the synced folder tree. Also check if `%USERPROFILE%\.openclaw\` (OpenClaw's config) appears in OneDrive — it's in USERPROFILE which may be synced on KFM-enabled accounts. | If LOCALAPPDATA files appear in OneDrive → F1.5 didn't actually prevent sync (unlikely — LOCALAPPDATA is excluded by Windows convention, but verify). If `.openclaw\` appears in OneDrive → OpenClaw config (including API keys in openclaw.json) is synced to cloud. This is an OpenClaw architectural issue, not a script bug, but worth knowing. |
| **7. Stage 10 onboarding TUI** | During openclaw onboard, verify: arrow keys navigate between options, all prompts render fully (no truncated text), the wizard questions match the Stage 10 cheat sheet. | TUI is garbled (call operator didn't fix it) → Mike can't complete onboarding. Prompts have changed since cheat sheet was written → Mike follows wrong instructions. Either case: screenshot + Shands. |
| **8. Stage 14 end-to-end with real Telegram** | Send "What is 2 + 2?" from a real Telegram account on a phone. Wait for reply. Answer "y" to both log verification questions. | Bot doesn't reply within 30 seconds → gateway or pairing issue. Log verification shows 0 matches for telegram or deepseek → `--limit 100` still insufficient OR log message format doesn't contain these keywords. |
| **9. Diagnostic script post-setup** | Run `Setup-MikeBot-Diagnostic.ps1` independently (right-click → Run with PowerShell). Verify all checks pass: internet, tools, port 18789, dashboard, gateway auth token, Telegram bot token, setup files. | Any `[FAIL]` line → that subsystem has a problem. Port 18789 not listening → gateway service didn't start. Telegram bot token missing → onboarding didn't configure the channel. |
| **10. Reboot persistence** | Restart the laptop. After login, wait 2 minutes. Run the diagnostic again. Verify gateway is running without manual intervention. Send another Telegram message. | Gateway not running after reboot → Windows Scheduled Task or Startup-folder fallback didn't work. This is an OpenClaw installer issue, not a script bug, but blocks Mike from having a working bot. |

## Conditions flagged as "needs real-laptop verification"
- SmartScreen dialog flow (varies by Windows build and browser)
- OEM AV behavior (varies by vendor, version, and trial state)
- OneDrive KFM behavior with `.openclaw\` config directory
- Gateway auto-start after reboot (depends on OpenClaw's Windows service mechanism, not the setup script)
